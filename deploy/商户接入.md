# 生产收款与人工审核

支付宝使用当面付预下单与 RSA2 异步通知。微信使用 Native 下单、微信支付公钥模式验签、API v3 密钥解密。申请产品时向支付平台如实说明多卖家平台、资金结算方式和商品类目，确认获批范围覆盖实际业务。当前实现记录平台单商户收款，开发者余额属于站内台账。

服务器的 `/etc/ai-supermarket/merchant.env` 由 root 管理。填入商户产品核准的信息，`PAYMENT_NOTIFY_ORIGIN` 使用支付平台认可且可从公网访问的源地址。微信应配置公开 HTTPS 回调。正式密钥通过 systemd 的 LoadCredential 向服务提供，备份密钥保存在 root 专用目录。不要提交密钥到 Git。

| 配置 | 所需值 |
| --- | --- |
| 支付宝 | ALIPAY_APP_ID、ALIPAY_SELLER_ID、ALIPAY_PRIVATE_KEY_FILE（PKCS8）、ALIPAY_PUBLIC_KEY_FILE（支付宝公钥） |
| 微信支付 | WX_APP_ID、WX_MCH_ID、WX_MCH_SERIAL、WX_PRIVATE_KEY_FILE、WX_PLATFORM_KEY_ID、WX_PLATFORM_KEY_FILE、WX_API_V3_KEY_FILE |

例如为服务添加 systemd drop-in，写入 `[Service]` 和 `LoadCredential=ali-private:/etc/ai-supermarket/keys/ali-private.pem`，再将环境文件的 `ALIPAY_PRIVATE_KEY_FILE` 指向 `/run/credentials/ai-supermarket.service/ali-private`。其他密钥同理。加载配置后重启服务。

异步通知路径分别为 `/v1/payments/notify/alipay` 和 `/v1/payments/notify/wechat`。每个渠道用实际准入商品逐笔核对平台交易号、商户订单号、支付金额、买家领取权限及重复通知的处理结果。

服务器操作员使用 SSH 查看待审卖家及商品：

```sh
sudo curl --unix-socket /run/ai-supermarket/review.sock http://localhost/pending
```

审核时向同一套接字 POST `/seller/用户ID` 或 `/offer/报价ID`，JSON 请求体为 `{"approve":true}` 或 `{"approve":false,"reason":"具体修改意见"}`。审核前核实商品内容、分发权、价格和交付页面。公网不提供该操作入口。
